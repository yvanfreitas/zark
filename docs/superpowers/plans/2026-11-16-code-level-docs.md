# Code-level documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate C4 level-4 code graphs (modules, exported pieces, calls) from TypeScript for each `component` with a `source`, commit them under `architecture/code/`, gate them in CI with `zark scan --check`, and browse them read-only in the UI.

**Architecture:** A pure extractor in `packages/core/src/code/` (parse one file → pieces + call sites; resolve imports; build one component graph) feeds a filesystem layer (`scanProject`) used by the CLI. Generated files are a new project file kind (`code`) loaded with the rest of the model, so validation, the HTTP snapshot, MCP and the UI read them like any other YAML.

**Tech Stack:** TypeScript (NodeNext), zod 4, `yaml` Document API (existing writer), `oxc-parser` (new, native, prebuilt), vitest, React + @xyflow/react + ELK worker (existing).

**Spec:** `docs/superpowers/specs/2026-11-16-code-level-docs-design.md`

## Global Constraints

- Node ≥ 22; published as `@ewcodes/zark`; `oxc-parser` added to `packages/cli` `dependencies` and to the esbuild `external` list in `packages/cli/build.mjs`.
- Languages v1: `.ts .tsx .mts .cts .js .jsx .mjs`. Default excludes: `**/*.test.ts`, `**/*.spec.ts`, `**/__tests__/**`, `**/*.d.ts`, `**/generated/**`.
- Byte-identical output for the same source on every OS: no timestamps, no absolute paths, no line numbers, `/` separators, LF, sorted (modules by path, pieces by name, edges by from/to/kind).
- Never guess an edge: anything not resolved by the spec's rules 1–4 increments `unresolved.calls`; bare/workspace package imports increment `unresolved.external`; calls into files no component claims increment `unresolved.unowned`.
- `source` (entity, component only) and `code` (zark.yaml) are additive under `schema: 1`; no migrate step.
- Filesystem validations (source matches nothing, tie) run only in `zark validate` and `zark scan`, never in `validate()` as called by `applyOps` or `projectAtRef`.
- Generated file header comment: `# Generated by \`zark scan\` from <source list>. Do not edit.`
- Self-calls (from === to) are not edges.

## Review Focus

1. A source file with a syntax error must not abort the scan: the module is listed with the pieces oxc still recovers, and the CLI summary prints `parse errors: <n>` for the component. (Task 3 test `recovers from syntax errors`.)
2. Windows checkouts (CRLF source, `\` paths from globbing) must produce the same YAML as Linux. (Task 5 test `crlf and backslash paths give identical output`.)
3. Circular imports and re-export chains (`export * from`, `export { x as y } from`) must terminate and resolve to the declaring module. (Task 4 test `re-export chains and cycles`.)
4. A component whose `source` exists but contains only excluded files is not "matches nothing": it gets an empty graph, not E014. (Task 2 test `source with only excluded files`.)
5. Default exports and anonymous default functions get the piece name `default`; importing them under any local name resolves to `default`. (Task 3 test `default exports`.)

### Task 5: Build a component graph (pure) and scan a project (filesystem)

**Files:**
- Create: `packages/core/src/code/graph.ts`, `packages/core/src/code/scan.ts`, `packages/core/test/fixtures/code/` (mini repo: `architecture/` with two components + `services/bot/**`, `services/moderation/**`, `services/shared/util.ts` unclaimed, a `tsconfig.json` with `paths`)

- Test: `packages/core/test/code-graph.test.ts`

**Interfaces:**
- Consumes: `extractModule`, `resolveSpecifier`, `resolveExport`, `loadAliases`, `claimFiles`.
- Produces:
  - `buildGraph(component: string, owned: string[], facts: Map<string, ModuleFacts>, owner: Map<string, string>, aliases: Aliases): { graph: CodeGraph; parseErrors: number }` — applies rules 1–4, method-level endpoints, aggregates counts, drops self-edges, sorts, fills `unresolved`. A `typed` hint resolves when `typeName` is an imported binding or local declaration that is a class/interface piece; member must exist in `members` for classes, otherwise falls back to the class itself.   - `scanProject(dir: string, opts: { check?: boolean; only?: string[] }): Promise<ScanResult>` where `ScanResult = { components: { id: string; file: string; status: 'written'|'unchanged'|'stale'|'deleted'; modules: number; pieces: number; edges: number; unresolved: CodeGraph['unresolved']; parseErrors: number }[]; problems: Problem[] }`. Parses only owned files plus files of other components that owned files import. Writes `architecture/code/<id>.yaml` via `createDoc('code', …)`/`toText` with the header comment, deletes files of components without `source`. With `check`, writes nothing and marks differing files `stale`.
